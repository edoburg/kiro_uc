# 生成設定の保存・読み込み

実装・検証日：2026年10月5日（日本時間）。作業開始時のmain `2391171` を基準とし、透過確認・拡大レビューとPython同梱インストーラーを維持した。

## 操作

1. 共通入力・企画編集・画像レビューの画面上部にある「生成設定の保存と読み込み」を使う。モデル・品質はこの作業の次回生成に適用され、グローバル設定は変更しない。
2. 保存名を入力して「名前を付けて保存」で新しい設定を作る。選択中の設定を更新する場合は「上書き保存」を押して確認する。日本語名と同名の複数設定を許可する。
3. 一覧に名前・更新日時・枚数・テーマを表示する。「読み込み」は未保存編集や画像・変換結果がある場合に置換の確認を行い、成功後に共通入力画面へ戻る。画像生成は開始しない。「スタンプ内容を作成」→企画確認→「画像を生成」で明示的に開始する。
4. 一覧の「別名保存」でアプリ内の名前入力欄を開き、「この名前でコピーを保存」で保存済みの条件を別IDのコピーとして保存する。現在の作業を切り替えない。「別名保存をキャンセル」はファイルを書き込まず、保存失敗時は入力名を保持して再試行できる。現在の編集を別名で保存する場合は上部の保存名を変更し、「名前を付けて保存」を使う。
5. 「削除」は確認して保存ファイルを削除する。現在の入力や確定済み条件は保持する。破損した設定は正常な一覧と分けて案内し、確認後に削除できる。
6. 共通入力と企画の編集中も下書きを保存できる。レビューでは確定済み条件だけを保存し、詳細モーダルの未確定編集は混ぜない。再生成に失敗した後も編集済みの次回条件を保存できる。

生成・変換・出力中は保存／読込と作業モデル・品質切替を無効にする。保存／読込中は生成開始と作業編集を無効にする。失敗は日本語で通知し、書込成功前には保存済みと表示しない。

## 保存形式と場所

Electronの `app.getPath("userData")/generation-presets/<UUID>.json` に保存する。通常のWindows環境ではアプリのユーザーデータ領域内になる。保存名をパスに使わず、preloadはlist/load/save/deleteの限定操作だけを公開する。

v1の保存形式は次のとおり。

```text
schemaVersion: 1
id: UUID
name: 保存名
createdAt / updatedAt: UTCのISO日時
request:
  prompt / theme / count / style（任意） / mode
  items[]:
    id / position / meaning / expression / pose / prop
    additionalInstructions / textEnabled / displayText
    sourceTemplateId（将来のテンプレート用・任意）
options:
  model / quality
```

項目順をそのまま保存し、positionは0始まりの連番、項目IDは一意のASCII安定ID（100文字以下）とする。保存可能な枚数は8/16/24/32/40。追加指示は500文字、共通プロンプト1000文字、意味・表情・ポーズ・小物は各100 UTF-16文字、描き文字は100 Unicodeコードポイント。displayTextのnullと空文字、textEnabled=falseを維持する。文字設定がない旧項目はfalse/nullに正規化する。

保存時には認証情報・画像data URL・一時パス・生成進捗・stream IDを含めない許可項目だけをコピーする。構造検証と生成時の必須値検証を分け、空欄や意味重複のある下書きを保存できる。読込時も検証し、256KiB超、破損JSON、不正なID／位置、未知フィールド、未知バージョン、シンボリックリンクを拒否する。

書込は一時ファイルへ書込・同期・クローズしてからrenameする。上書き失敗時は元ファイルを維持し、変更操作をリポジトリ内で直列化する。読み込み成功時はdraftRequestとフォームを同時に復元し、currentRequest・旧画像・変換・アップロード結果を外す。

テンプレート選択機能は未実装。sourceTemplateIdはv1の任意メタデータとして保存でき、生成API要求からは除外する。項目配列が選択と並び順のスナップショットになる。セット単位の選択ID等を追加する場合は、schemaVersionを上げ、許可フィールドと明示的な移行関数を追加する。旧保存設定を新しい定型データの先頭N件へ置き換えない。
