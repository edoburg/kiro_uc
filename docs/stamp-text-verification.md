# 画像ごとの手書き文字設定：実装と検証

2026年10月3日

## 実装

- 新規企画は文字あり・意味を使用。旧項目と旧API要求は文字なしとして扱う。
- 各行の「文字を入れる」「画像に描く文字」「意味を使用に戻す」で設定する。意味使用中は意味編集に追従し、任意文字は独立する。オフ時も入力を保持する。
- 空白だけの文字ありを拒否する。任意文字はオフ時も100文字上限を検証する。表示文字の重複は許可し、意味の重複は従来通り拒否する。
- 文字ありではAIに丸く柔らかな手書き文字とイラストを一体で描かせる。文字設定は共通設定・追加指示より優先し、既存の追加指示は保持する。
- レビューは画像の生成時設定を表示する。対象だけの再生成、キャンセル、失敗後の旧画像保持、編集済み条件での再試行に対応する。
- requirements.md、design.md、tasks.mdを更新した。企画のファイル保存機能は現状存在せず、状態・要求・IPCコピーで文字設定を保持する。

## 検証結果

外部の有料画像APIは呼んでいない。

標準設定の圧縮テストと対象サービスには変更がなく、文字設定から独立した既存の時間制限失敗。型・文字設定・再生成の回帰失敗は検出されなかった。サンドボックス内の初回実行は子プロセス起動や一時ファイルの権限で失敗したため、承認された制限外実行で再検証した。

モックは意味追従・任意文字の保持・意味に戻す操作、null/空文字/falseのIPCとAPI変換、混在セット、先頭プレビューと残りの承認生成、非先頭再生成・再試行、キャンセル、成功画像の文字設定と失敗時の旧画像保持を検証する。

## 実画像8枚の確認手順（ユーザーが実行）

1. アプリを起動し、共通キャラクター、日常の挨拶、8枚を選び企画を作成する。
2. 1～3枚目は初期状態の「文字あり・意味を使用」のままにする。1枚目の意味を編集し、文字入力欄も追従することを確認する。
3. 4～6枚目は「画像に描く文字」を「おやすみ！」「OK」「OK」に変更する。同じ表示文字でも意味は別のままにする。
4. 7～8枚目は「文字を入れる」をオフにする。7枚目で任意文字を一度入力してからオフ→オンと操作し、保持を確認して再びオフにする。
5. 「画像を生成」で一括生成する。承認フローも確認する場合は共通設定でプレビュー承認モードを選び、先頭確認後に残りを生成する。
6. レビューの「生成に使った文字」と画像を比較し、指定文字・記号、誤字、読みやすさ、顔との重なり、画像内の収まり、文字なし2枚に余計な文字がないことを目視確認する。
7. 4枚目の「再生成」で文字を編集し、まずキャンセルする。画像と確定条件が維持されることを確認する。再度開いて確定し、対象だけが更新されることを確認する。
8. LINE規格へ変換し、スタンプ・サムネイル・メイン画像を確認する。

## 制約

文字の完全な正確さはAI生成では保証できず、目視確認が必要。OCR、後からのフォント合成、自動誤字修正は実装していない。実画像の生成・文字品質の確認、アプリ画面の実機確認は今回未実施。

スタンプとサムネイルは画像全体を縮小する。メイン画像は既存の正方形中央クロップを使用するため、画像端の文字が切れる可能性がある。今回の変更では画像処理を改修していない。
